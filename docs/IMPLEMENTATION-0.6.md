# Асси 0.6 — папки, пауза передачи и отдельные сеансы

Продолжение выбранных направлений 1/3/4/5. Поиск по ID и автоматический NAT traversal
не добавляются. Список остальных направлений остаётся в [отчёте 0.5](IMPLEMENTATION-0.5.md).

## Функции

- Передача папки со структурой и пустыми каталогами. Отправитель выбирает папку
  системным диалогом; получатель явно выбирает «Принять и распаковать» и каталог
  назначения. Данные публикуются в новую папку без перезаписи существующего дерева.
  Альтернативно пакет можно сохранить обычным файлом.
- Потоковый внутренний контейнер ASSIFOLD v1: без сжатия, до 1 ГиБ вместе с
  заголовками, 10 000 элементов, глубина 32. Проверяются целостность, относительные
  пути, повторения, Unicode/case collisions; ссылки и специальные файлы не принимаются.
  Это не произвольный ZIP-распаковщик и не удалённый файловый менеджер.
- Пауза передачи с подтверждённым смещением. Для продолжения сверяются сохранённая
  часть, SHA-256, исходный размер/метаданные. Продолжение запрашивает отправитель,
  подтверждает получатель. Пауза сохраняет очередь занятой; отмена удаляет partial.
- Главное окно и до четырёх дополнительных viewer-окон на desktop. У каждого свой
  SessionEngine, ввод, видео, звук, файлы и запись. Переключатель показывает настоящие
  окна. Это отдельные окна с переключателем, не встроенные вкладки видеоповерхностей.
- Только главное окно предоставляет входящий доступ и меняет общие настройки.
  Дочерние окна могут подключаться к другим устройствам. Закрытие одного очищает
  только его сеанс, выход из приложения — все сеансы.

## Исправление разрешений 0.5

Новые IPC-команды 0.5 были зарегистрированы в handler, но отсутствовали в AppManifest
и capability главного окна. При включённом app ACL Tauri отклонял их до handler;
тесты ядра и браузерный mock-стенд не проверяли этот слой.

Теперь `src/ipc_catalog.rs` задаёт полный каталог команд и subset для viewer-окон;
`build.rs` генерирует разрешения, capabilities используют явные allowlists.
Окно пометок остаётся только для чтения. RemoteSession выбирает engine по реальному
WebView label, а не по переданному из JS имени окна. RecordingSession так же
изолирует запись. Добавлены проверки каталога/permissions и тест фактической
обработки IPC через mock runtime Tauri с настоящим сгенерированным ACL.

## Ограничения

- Продолжение работает в том же соединении. После полного разрыва временный файл
  удаляется: постоянные checkpoints, привязка к peer и восстановление после
  переподключения ещё не реализованы.
- Android пока не имеет выбора/сохранения папок через SAF и нескольких desktop-окон.
- Аппаратное кодирование, системная служба до входа, UAC, голос, туннели, privacy,
  камера и удалённая печать остаются отдельными задачами. Срез 0.6 их не завершает.
- Протокол приглашений обновлён до версии 4. Обновить нужно обе стороны; приглашения
  прежних версий следует создать заново.
- Визуальная проверка 0.6 через браузер пока не выполнена: CUA не предоставил браузер,
  попытка native Chrome завершилась таймаутом. Снимок и проверка размеров 0.5 не
  считаются подтверждением нового интерфейса. Физические устройства также не проверены.

## Проверки

`npm run check` прошёл: **163 Rust-теста, 61 UI-тест и 4 проверки IPC-каталога**,
синтаксис JS, rustfmt, Clippy workspace/all-targets с `-D warnings` и doctests.
Нативные тесты включают настоящий сгенерированный ACL в mock runtime Tauri,
два независимых TLS-сеанса, очистку при разрыве и контроль границ viewer-окон.

Собраны macOS arm64 debug `.app` и Android arm64 debug APK; версия 0.6.0
проверена в обоих пакетах. Пути и SHA-256: `.validation/v6-artifacts.json`.
Clippy модуля `assi-folders` для `x86_64-pc-windows-gnu` прошёл с `-D warnings`.
Полные Windows/Linux сборки не выполнялись.

Независимый статический review выявил удержание staging после пассивного разрыва
и публикацию папки по заменяемому пути Windows. Исправлены барьером завершения
файловых задач и операциями относительно открытого дескриптора каталога.
Регрессии входят в общий check; Windows runtime требует отдельной проверки.
Закрытие окна теперь завершается и при ошибке очистки сеанса, без зависшего окна.

Итоговые результаты фиксируются в `.validation/v6-*`. Тесты файлов используют
временные каталоги; тесты сети — loopback TLS. Ни блокировка/перезагрузка компьютера,
ни предоставление реального экрана, ни включение автозапуска в этих тестах не выполняются.
