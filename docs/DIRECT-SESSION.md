# Прямой сеанс в Асси 0.2.0

Это первая рабочая реализация транспортного ядра, а не готовый публичный сервис.
Передача идёт напрямую между IP-адресами; серверные коды из адресной книги пока
не разрешаются. В разных сетях без прямого маршрута соединение не установится.
Приглашения не сохраняются в базе и не следует публиковать их в открытом доступе.

## Как подключить два устройства

1. На компьютере, экран которого нужно показать, открыть «Предоставить доступ».
2. Указать его IP в общей сети. Значение 127.0.0.1 предназначено только для
   проверки на том же компьютере. Нажать «Включить приём».
3. Передать приглашение другому участнику по доверенному каналу.
4. На втором устройстве открыть «Сеансы» → «Подключиться» и вставить приглашение.
5. На первом компьютере открыть входящий запрос и разрешить просмотр.
   Для управления отдельно отметить мышь/клавиатуру; без отметки доступен просмотр.
6. В любой момент нажать «Завершить сеанс». Приглашение однократное: для повторного
   сеанса снова включить приём и получить новое.

macOS потребует разрешения «Запись экрана», а для управления — «Универсальный
доступ» в настройках системы. Само открытие приложения не запускает захват.
Windows firewall может блокировать входящее соединение; приложение не меняет
правила firewall автоматически. На Android сейчас доступен просмотр другого
компьютера, передача экрана телефона не реализована.

## Что реализовано

- TLS через rustls, доверие сертификату из приглашения, случайный секрет 256 бит.
- Подтверждение конкретного запроса владельцем, срок ожидания 60 секунд.
- JPEG основного монитора через xcap, размер до 1920 по длинной стороне/4 MiB.
- Последний кадр вместо растущей очереди; кадры передаются в WebView бинарным IPC.
- Раздельные права просмотра/ввода, ограниченные очереди, heartbeat и отключение.
- Нормализованные координаты мыши, основные клавиши, латинские буквы и цифры.
- Отпускание ввода при потере фокуса, отключении и обычном выходе приложения.
- Ошибки разрешений ОС показываются пользователю и прекращают сеанс.

## Что ещё не готово

NAT traversal/relay, сервер кодов и учётных записей, передача файлов, звук,
аппаратное видео, несколько мониторов, системные сочетания/secure desktop,
синхронизация раскладок/IME, кириллица, экран Android/MediaProjection,
управление Wayland через портал, подписанные релизы и обновления.
JPEG-поток предназначен для первого прямого сеанса; измерений задержки и расхода
трафика на физических машинах пока нет. Это не заявляется как замена видеокодеку.

## Доказательства и границы

Rust-тесты соединяют два движка настоящим TLS по loopback, передают синтетический
JPEG и события, проверяют отказ, тайм-ауты, лимиты и отзыв доступа. Они не получают
пиксели рабочего стола и не нажимают клавиши ОС. Нативные адаптеры скомпилированы
на macOS, Android собирается как viewer; Windows/Linux требуют сборки на своих ОС.
Сеанс между двумя физическими устройствами и системные разрешения ещё нужно
проверить вручную по сценарию выше. Независимый review закрыт; это не внешний
аудит безопасности продукта.
