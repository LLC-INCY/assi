## Что сравниваем

RustDesk использует компактную панель с меню управления, изображения, клавиатуры,
общения, записи и переключением мониторов. Некоторые элементы показываются только
при поддержке текущей платформой/типом соединения. В его настройках отдельно
управляются аудио, буфером, файлами, качеством/FPS, приватностью и записью.
Источники: [код панели, `_buildToolbar`, `_KeyboardMenu`](https://github.com/rustdesk/rustdesk/blob/master/flutter/lib/desktop/widgets/remote_toolbar.dart),
[официальные настройки](https://rustdesk.com/docs/en/self-host/client-configuration/advanced-settings/).
Это ориентир состава функций; код RustDesk в Асси не копируется.

| Группа | Сейчас в Асси | Следующий законченный результат | Зависимость / проверка |
| --- | --- | --- | --- |
| Экран | JPEG выбранного владельцем монитора; вписать, 50–400%, перемещение, полноэкранный режим; качество low/balanced/high 6/8/12 FPS | Удалённое переключение монитора с подтверждением кадра и единым screen epoch | Выбор дисплея должен менять capture, координаты ввода и область пометок одним действием; проверка разных DPI |
| Мышь | Указатель, три кнопки, прокрутка двух осей, локальный обзор без ввода | Настройки колеса и удобный тачпад на Android viewer | Различать жест просмотра и удалённый жест; сброс зажатых кнопок при потере фокуса |
| Клавиатура | Меню F1–F12/служебных клавиш и сочетаний; поле Unicode-текста, физическая латиница и цифры | Полная IME/физические раскладки, тач-клавиатура без текстового поля | Физические клавиши и ввод текста — разные операции; IME/composition тестируются отдельно |
| Системный звук | macOS 13+ ScreenCaptureKit и Windows WASAPI; TLS PCM48k stereo, согласие владельца, mute и громкость; воспроизведение через WebAudio | Capture Linux/Android, сжатие Opus, физическая проверка устройств | Отдельные backend по ОС; ограниченная очередь, обработка смены устройства/разрыва |
| Микрофон / голос | Не реализован | Отдельное подключение голоса, независимое от звука рабочего стола | Системное согласие на микрофон, эхо/обратная связь; не включать вместе с системным звуком неявно |

| Файлы | Desktop: один файл до 1 ГиБ, согласие, SHA-256, отмена; компактный вызов из панели | Android SAF; очередь нескольких файлов | Никакого произвольного сетевого пути; защита от перезаписи сохраняется |
| Рисование | Общие перо, стрелка, рамка, цвета, undo своего и очистка | Компактное контекстное меню и физическая проверка наложения | Нормализованная общая доска; никакого OS-ввода в режиме рисования |
| Снимок / запись | PNG с пометками на desktop; видеозаписи нет | Запись с индикатором и ограничением ресурсов; сохранение на Android | Для видео — кодирование, таймстампы и завершение контейнера при сбое |

| Диагностика | Состояние соединения и ошибки | Компактные сведения: маршрут, разрешение, FPS, объём/скорость, задержка | Измерять фактические значения; настройка FPS не равна достигнутому FPS |
| Системные действия | Завершение сеанса | Блокировка, перезапуск, Ctrl+Alt+Del, elevation — отдельный этап | Платформенные полномочия/служба, явное согласие, устойчивое переподключение |

## Минималистичная панель

Проектное решение для Асси: одна строка небольших иконок — управление/обзор,
экран, клавиатура, звук, файлы, рисование, дополнительные действия, завершение.
Desktop: визуальный размер кнопки около 36 px; сенсорный hit area не менее 44 px.
На узком экране второстепенные действия переходят в «Ещё»; не создавать несколько
рядов больших подписанных кнопок поверх изображения.

Каждая иконка имеет tooltip, `aria-label`, видимый focus и выделенное состояние.
Одновременно открыто одно меню. Escape закрывает меню и возвращает фокус кнопке;
только после закрытия меню клавиатура снова может управлять удалённым устройством.
Перо/цвет/толщина появляются в меню рисования, не занимают постоянную вторую панель.
Завершение всегда доступно и отличается цветом; его нельзя спрятать в автоскрытии.
Внутри меню остаются текстовые подписи, поскольку распознавание иконок не должно
быть условием работы с приложением.

Недоступные возможности не изображают работающие переключатели: меню объясняет,
что отсутствует — разрешение, поддержка платформы или реализация. Глобальные
«поддерживается» и «разрешено в этом сеансе» хранятся раздельно.

## Платформенные границы

| Платформа владельца | Экран и ввод сейчас | Аудио и системные действия |
| --- | --- | --- |
| Windows | Desktop capture/input; физическая проверка сборки ещё нужна | Реализован WASAPI loopback и передача звука; нужна физическая проверка. UAC/elevated UI требуют соответствующих полномочий; обычный процесс не обещает управление ими |
| macOS | Capture и Accessibility после согласия ОС; overlay реализован, физически не проверен | Реализован ScreenCaptureKit audio → PCM → TLS → WebAudio, macOS 13+; нужна физическая проверка устройств и разрешений |
| Linux X11 | Capture/input; overlay отключён из-за исключения из захвата | Backend звука должен работать с действующим PulseAudio/PipeWire окружением; не подменять звук системы микрофоном |
| Linux Wayland | Удалённый ввод пока отсутствует | Нужен portal/backend; поведение зависит от compositor. Не обещать login screen и универсальный unattended-доступ |
| Android | MediaProjection host без удалённого управления; viewer и общая доска в приложении | Playback capture начиная с Android 10, `RECORD_AUDIO` и согласие MediaProjection; захват зависит от политики приложения-источника. Микрофон — отдельная функция |

WASAPI loopback захватывает выходной endpoint в shared mode, а не обычный
микрофонный input. [Microsoft: Loopback Recording](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording).
ScreenCaptureKit предоставляет настройки аудиопотока, включая sample rate и число
каналов. [Apple: Meet ScreenCaptureKit](https://developer.apple.com/videos/play/wwdc2022/10156/).
Android требует действующий MediaProjection, разрешение записи аудио и выполнение
условий capture policy; при отзыве токена поток должен останавливаться.
[Android: Capture video and audio playback](https://developer.android.com/media/platform/av-capture).

Ctrl+Alt+Del нельзя реализовать как обычные три `KeyDown`: Windows предоставляет
SendSAS с требованиями к службе либо `uiAccess` и системной политике.
[Microsoft: SendSAS](https://learn.microsoft.com/en-us/windows/win32/api/sas/nf-sas-sendsas).
RustDesk также отделяет elevation от стандартного сеанса; удалённый запрос elevation
требует подтверждения UAC на стороне владельца.
[RustDesk: Windows Portable Elevation](https://rustdesk.com/docs/en/client/windows/windows-portable-elevation/).
Его Linux-документация отдельно оговаривает экспериментальность Wayland и ограничение
login screen. [RustDesk: Linux](https://rustdesk.com/docs/en/client/linux/).
Android-документация различает мышь/тач, input service, файлы и внутренний звук;
это независимые разрешения и реализации. [RustDesk: Android](https://rustdesk.com/docs/en/client/android/).

## Порядок интеграции

1. Компактная панель над уже работающими функциями. Проверка focus, overlay/expanded,
   320 px, landscape, клавиатуры, отсутствие ввода при работе с меню.
2. Базовая клавиатура целиком, меню сочетаний и Unicode-текст; явный обмен текстом.
   Каждый пакет относится к текущему request ID и разрешению ввода/буфера.
3. Системный звук как вертикальный срез на каждой ОС: согласие, источник,
   ограниченный поток, playback, mute/volume, отмена, физические тесты. Наличие
   одного аудиопакета в протоколе ещё не означает готовый звук.
4. Мониторы и качество; снятие/смена монитора во время управления. Затем показатели
   производительности, снимок, запись и чат.
5. Службы ОС, elevation, безопасный reconnect, системные команды и privacy mode.
   Эти возможности не объявлять завершёнными после добавления пунктов меню.

Протокол возможностей нужен до расширения списка: совместимая версия, поддержка
функции на peer, текущее согласие и причина недоступности. Приоритет пользовательского
ввода и небольших управляющих сообщений должен сохраняться при передаче файлов,
видео и аудио. Проверять ограничение памяти и очищение очередей при смене сеанса.

## Ограничения текущего рабочего блока

- Выбор монитора доступен владельцу в режиме только просмотра. При разрешённом управлении сервер запрещает смену: старый ввод не должен попасть на новый монитор до получения нового кадра. Для снятия ограничения нужен screen epoch/ack во всём пути frame/input. Качество менять можно.
- На дополнительном мониторе наложение поверх окон отключено, пометки остаются в общей доске. Поздний штрих, начатый на предыдущем кадре, может появиться после смены экрана; его можно удалить.
- macOS сборка теперь требует 13+, поскольку включает ScreenCaptureKit. Звук передаётся без сжатия (около 192 КБ/с для стерео); это ранняя реализация, ещё не Opus.
- «Ещё → Сохранить кадр с пометками» сохраняет PNG через системный диалог на desktop без перезаписи. Android сохранение пока отключено. Видеозапись сеанса не реализована.
- Служба unattended access, UAC/secure desktop/CtrlAltDel, удалённый restart, голосовой звонок, чат, синхронизация буфера в обе стороны, Android SAF и аппаратный видеокодек остаются этапами реализации. Не показываем фиктивные кнопки этих функций.
