- Реализован протокол общих пометок: оба участника, host-ordered изменения,
  128 штрихов ×128 точек, валидируемые координаты, undo собственного штриха/clear.
- Режимы управления/обзора/рисования разделены. Рисование не отправляет ввод в ОС.
- macOS/Windows системный звук: opt-in capture, ограниченный PCM/TLS-канал,
  WebAudio, громкость/mute, атомарный audio epoch и очистка при отзыве.
- Нативный выбор монитора разрешён владельцу только в режиме просмотра.
  Для безопасного переключения при управлении нужен сквозной screen epoch.
  Поздний штрих со старого кадра после переключения может потребовать удаления.
- Наложение поверх окон доступно на основном мониторе macOS/Windows. Его
  исключение из захвата, прозрачность, DPI и поведение поверх полноэкранных окон
  требуют физической проверки. Linux/Android показывают общие пометки внутри Асси.
- Capture аудио Linux/Android, полная синхронизация буфера, видеозапись, голосовой
  звонок, Android SAF и системная служба/UAC/CtrlAltDel ещё не реализованы.
- Захват экрана, звук, OS input и доступ к реальным файлам пользователя при
  автоматических проверках не запускались. Реальный сеанс двух устройств,
  разрешения/отказ и отзыв доступа надо проверить перед выпуском.

# Проверка реализации 0.3.0 — 3 ноября 2026

Актуальный результат. Ниже сохранена история 0.2/0.1; прежние списки
«не реализовано» не заменяют текущую инструкцию `docs/REMOTE-SESSIONS.md`.

## Автоматические и независимые проверки

- `npm run check`: код возврата 0. Синтаксис UI, rustfmt, clippy workspace/all-targets
  с `-D warnings`, **62 Rust-теста + 12 Node/UI-тестов** успешно.
- В Rust-набор входят 9 relay-тестов и 34 session-теста с настоящими loopback
  TLS-соединениями. Проверен вложенный TLS через relay, подмена внутреннего
  сертификата, файлы в обоих направлениях, отдельное согласие, SHA-256/offset/размер,
  нулевые файлы, no-overwrite, отмена и очистка, изменение исходного файла,
  expiry и остановка между sync и публикацией.
- Android: Kotlin compile и **8 JVM-тестов** SessionGate/CaptureStore успешно;
  XML-результаты в `apps/client/android-host/android/build/test-results`.
- Независимый reviewer повторил 9 relay + 34 session + 8 UI тестов, проверил
  границы ACL, отмену native захвата и cleanup. Его замечания о поздней публикации
  файла, задержке native release на медленном диске и Android late/error callbacks
  закрыты. Открытых high/critical в просмотренной области не осталось.
- UI: 18 сочетаний размеров для incoming-file, file-progress и Android consent
  от 320×568 до 1440×900, включая 600×360 и границу760/761. Горизонтального
  переполнения нет; прогресс файла не пересоздаёт focused remote-screen.
  Проверено переключение direct/relay в диалоге: скрытое IP-поле disabled,
  конфигурация сервера required; диалог без горизонтального переполнения.

## Сборки

- macOS arm64 debug `.app` **0.3.0**: успешно, код возврата 0.
- Android arm64 debug APK **0.3.0**: успешно, код возврата 0. Merged manifest
  включает `app.assi.capture.CaptureService` и `FOREGROUND_SERVICE_MEDIA_PROJECTION`;
  Tauri подключил постоянный Android plugin module. Java target8 предупреждения
  остаются предупреждениями toolchain, не ошибками сборки.
- Windows/Linux сборки не выполнялись в этой macOS-среде.

Логи: `.validation/v3-validation.log`, `v3-macos-build.log`, `v3-android-build.log`.
Метрики UI: `.validation/v3-responsive.json`; снимок:
`.validation/v3-file-consent.png`. Хеши артефактов: `.validation/v3-artifacts.json`.

## Границы проверки

Использовались синтетические кадры, временные тестовые файлы и loopback. Не
запускались захват рабочего стола, системный ввод, OS permission dialogs и публичный
сервер. Физический Android MediaProjection, файловые native pickers, rotation,
блокировка, stopnotification, два клиента в разных сетях и реальные latency/traffic
требуют ручной проверки. Ревью не является внешним security-аудитом.

Android Storage Access Framework для файлов, управление Android, регистрация и
короткие серверные коды, публичный relay, аппаратное видео/звук, Wayland control и
подписанные релизы ещё не готовы. Реализованный relay не называется развернутым
облачным сервисом или полноценным NAT traversal с hole punching.

# Проверка реализации 0.2.0 — 3 ноября 2026

Текущая версия: прямой TLS-сеанс и нативный media bridge. Сведения о 0.1.x ниже
сохранены как история и не описывают текущую функциональность.

## Результат проверок 0.2.0

- `npm run check`: успешно; синтаксис обоих UI-модулей, 9 Node regression-тестов,
  rustfmt, clippy всех workspace targets с `-D warnings`, 35 Rust-тестов.
- Из них assi-session: 2 wire unit + 14 интеграционных тестов настоящего TLS по
  loopback с синтетическим JPEG. Проверены consent, wrong secret/certificate,
  запрет ввода без control, срок согласия, лимиты/очереди, stop/restart/socket close.
- assi-platform: 8 pure-тестов координат/клавиш/JPEG/ленивой инициализации.
- Native bridge: regression `stop_revokes_before_waiting_for_busy_media` подтверждает

  повторил 5 session UI-тестов и тест остановки. CloseRequested и ExitRequested

  мобильный фильтр сохраняет доступность после расширения, ошибка имени получает
  фокус. Подробности в `docs/DESIGN-AUDIT.md`.

Логи: `.validation/core-validation.log`, `core-macos-build.log`,
`core-android-build.log`. Приглашения, снимки рабочего стола и ключи туда не писались.

## Не проверено / не готово

Физический сеанс между компьютерами, разрешения захвата/ввода ОС, реальные latency

macOS-приложение 0.2.0 и APK собраны, но новый нативный runtime на физических
устройствах не запускался. Нет relay/NAT traversal, серверных кодов, файлового
канала, аппаратного видео, Android host и управления Wayland. Полный сценарий и
границы текущего ядра: `docs/DIRECT-SESSION.md`. Полностью готовым продуктом для
всех платформ эта версия не называется.

# Проверка реализации 0.1.0 — 3 ноября 2026

Область: первый локальный клиент. Проверки старого демонстрационного макета находятся отдельно в VALIDATION.md.

## Автоматические проверки

- Rust: 10 тестов — адресная книга и профиль после перезапуска; недопустимые/повторные коды; имя и тема; удаление; SQL-строка как данные; неизвестная платформа/группа; отказ без согласия и отзыв управления; запрет расширения прав; ошибка новой схемы с возможностью повторной попытки; сохранность повреждённого файла БД.
- JavaScript: 4 регрессионных теста исполняют реальные add/remove handlers с отложенным IPC. Успех и ошибка после закрытия/смены диалога не закрывают новое окно и не записывают в чужую форму.
- `cargo clippy --workspace --all-targets --locked -- -D warnings`: без предупреждений.
- `cargo fmt --all -- --check`, `node --check apps/client/ui/app.js`: без ошибок.
- `npm install --ignore-scripts`: npm audit сообщил 0 уязвимостей в 3 пакетах. Это не аудит Rust-зависимостей или всего продукта.

## Сборки и запуск

- macOS Apple Silicon: debug `.app` собрана. При первом открытии через CUA подтверждены нативное окно, загрузка профиля из Rust, своё устройство, разделы и честный статус отсутствующего кода.
- Последующая автоматизация окна через CUA возвращала тайм-ауты. Полный сценарий добавления, изменения настроек и перезапуска в нативном UI не подтверждён; для него есть пошаговая инструкция в DEVELOPMENT.md. Сохранение проверено интеграционными Rust-тестами.
- Android arm64: Debug APK успешно собран (CLI exit 0), проверена целостность ZIP и наличие lib/arm64-v8a/libassi_client.so. В логах есть предупреждения устаревших Gradle/Kotlin/Java API из шаблона Tauri; это не исправлялось правками внешних зависимостей. Запуск на телефоне/эмуляторе не проверен.
- Windows и Linux: исходники подготовлены в общей оболочке; сборки и запуск на этих ОС не проводились.

## Ревью

Независимое read-only ревью обнаружило два P2: гонку диалогов при позднем ответе IPC и выход приложения при ошибке открытия БД. Оба исправлены и покрыты регрессиями. Повторное ревью исправлений: **ship для локальной ранней сборки**. Reviewer повторно запустил 4 Node-теста; Rust и native UI независимо не повторял.

## Не реализовано

Сервер, удалённые подключения, идентичность peer/ключи, захват экрана, видеотранспорт, удалённый ввод, передача файлов, платежи, подписанные публичные релизы. Модель согласия в Rust — основа политики для будущего сетевого адаптера, не готовый механизм защиты соединений.

## Исправление адаптивности 0.1.1

Воспроизведение до исправления с 24 сохранёнными устройствами: окно 900×500 получало страницу высотой 1655 px; нижняя полоса находилась на y=1654. На 320×480 страница растягивалась до 3102 px.

После исправления в браузере проверен тот же UI из dist с отдельной тестовой реализацией load_snapshot (без доступа к SQLite): 51 сочетание трёх разделов и 17 размеров от 320×240 до 2560×1440. Проверены отсутствие горизонтального переполнения, высота оболочки, доступность footer и изменение навигации между 760 и 761 px. Дополнительно проверены 900×240 и 1180×320. Длинные имена и 24 устройства не растягивают страницу. Диалог добавления при 320×480 имеет размеры 296×456, остаётся внутри viewport и прокручивается вертикально. Кнопка добавления в конце длинного мобильного списка доступна через прокрутку.

Метрики: `.validation/responsive-before.json`, `responsive-after.json`, `responsive-final.json`. Воспроизводимый стенд: `npm run ui:build && node scripts/responsive-review.mjs`, затем `python3 -m http.server 8767 --bind 127.0.0.1 --directory .validation/responsive`. Это dev-only fixture, не часть app bundle. Проверка физических Android safe-area, клавиатуры и нативного изменения окна не заявляется выполненной. Изменение не затрагивает Rust-хранилище и протокол.

Сборки 0.1.1 macOS Apple Silicon (.app) и Android arm64 (debug APK) завершились с exit 0 после последней правки CSS. Версия macOS подтверждена по Info.plist. Повторно прошли 4 Node-регрессии и cargo check --workspace. Скриншот сравнения: `.validation/responsive-comparison.png`.
