# Асси: архитектура 0.4.0

Локальная адресная книга и настройки дополнены прямым/relay TLS-сеансом и файловым каналом с явным подтверждением владельца. Сетевой транспорт и системные адаптеры разделены. Демонстрационный прототип остаётся отдельно в `prototype/`.

## Решение по клиенту

Общее ядро написано на Rust. Для оболочки выбран стабильный Tauri 2; версии закреплены в Cargo.lock и package-lock.json. HTML/CSS/JavaScript отвечают за представление и вызывают узкий Rust API. Это позволяет перенести утверждённый интерфейс без смены визуального направления. Предварительная кандидатура Slint из PRODUCT-BRIEF.md заменена этим решением. JPEG передаётся бинарным IPC через `tauri::ipc::Response`; оптимизированный видеокодек остаётся следующим этапом.

Tauri поддерживает desktop и Android, но наличие поддержки фреймворка не доказывает работу приложения на каждой ОС. [Официальные требования](https://v2.tauri.app/start/prerequisites/), [вызовы Rust](https://v2.tauri.app/develop/calling-rust/), [разрешения](https://tauri.app/security/capabilities/).

## Структура

- `crates/assi-core`: SQLite-хранилище, типы платформ/групп/настроек, валидация и модель согласия на будущий сеанс.
- `crates/assi-session`: TLS, приглашение, согласие, сроки, ограниченные очереди frame/input/files, host-ordered общие пометки и PCM audio с epoch отзыва.
- `crates/assi-relay`: ограниченный TLS relay с одноразовыми комнатами; внутри него отдельное end-to-end TLS клиента.
- `apps/client/android-host`: постоянный Tauri/Kotlin MediaProjection plugin, вне генерируемого Android проекта.
- `crates/assi-platform`: ленивые xcap/enigo адаптеры, выбор монитора, Unicode/клавиши и профили JPEG.
- `crates/assi-audio`: opt-in системный звук macOS ScreenCaptureKit/Windows WASAPI; никаких устройств в конструкторе и микрофона.
- `apps/client/src-tauri`: IPC, lifecycle, хранение и media pump вне UI-потока.
- `apps/client/ui`: реальный интерфейс без демонстрационных устройств и сеансов.
- `scripts/build-ui.mjs`: собирает UI и переносит стили, шрифт, ноутбук и SVG-иконки из утверждённого прототипа в `apps/client/dist`.
- `prototype`: визуальный эталон и автономный демонстрационный макет.

## Данные

SQLite находится в системном каталоге данных приложения `app.assi.client`. На macOS: `~/Library/Application Support/app.assi.client/assi.sqlite3`. Профиль инициализируется один раз, UUID установки сохраняется. Этот UUID не является ключом, удостоверением личности или кодом подключения.

В базе хранятся имя текущего устройства, тема и адресная книга (UUID записи, название, девятизначный код, ОС, группа). Код адресной книги пока только метаданные; сервер ещё не назначает коды и не проверяет их существование. Статус удалённых устройств неизвестен. Собственного кода подключения в этой версии нет.

Запись выполняется параметризованными запросами. Создание схемы и добавление записи транзакционные. Новая неизвестная версия схемы отклоняется без перезаписи. Ошибки чтения не подменяются пустой базой. База не содержит ключей, файлов или экранного содержимого и не заявляется как зашифрованное хранилище.

## Границы доступа

WebView загружает только включённые в сборку ресурсы. CSP запрещает внешние скрипты, фреймы, формы и внешние сетевые запросы. Capability `main-local` разрешает только перечисленные команды хранения и сеанса только локальному главному окну. Плагины shell, файлового доступа, HTTP и произвольного выполнения кода не подключены.

IPC принимает типизированные данные; названия и коды повторно проверяются в Rust. В DOM все переменные строки экранируются. Детальные сообщения SQLite не передаются в UI.

Модель `consent::Session`: Pending → Accepted → Active → Closed. Управление возможно только в Active с разрешением control; control требует view, права не могут превышать запрошенные. Закрытие окончательное. Это модель политики, не законченная система аутентификации: сетевой адаптер должен удостоверить peer и источник согласия, связать ответ с конкретным запросом и сроком действия.

## Прямой сеанс

Контракт и trust model: `crates/assi-session/README.md`; ограничения ОС: `crates/assi-platform/README.md`. Приглашение включает эфемерный сертификат и секрет, не сохраняется. Native bridge связывает input с request_id и прекращает доступ до ожидания OS cleanup; CloseRequested и ExitRequested проходят через shutdown. Отдельная legacy-модель `assi-core::consent` не является runtime сетевого движка.

## Файлы и Android

Файловые пути выбираются только системным desktop picker в Rust, не принимаются из WebView/сети. Файловое состояние привязано к request_id/transfer_id; принимающий пользователь подтверждает отдельный файл. Disk I/O выполняется отдельно от состояния сеанса. Publication — только после длины/hash и повторной проверки отзыва, без перезаписи; native cleanup идёт параллельно завершению файловых операций.

Android разрешает только просмотр: native boundary вызывает MediaProjection после локального нажатия и до сетевого accept, повторно проверяет ID запроса. System permission не удерживает lifecycle lock; ошибки/поздние callbacks останавливают только свой request. Plugin не выдаёт WebView capability на capture-команды.

## Следующие этапы

1. Rust-сигнализация и идентичность: серверные коды, защищённая регистрация, ограничение перебора, подтверждение запроса на втором клиенте, тайм-аут и отмена. Публичное развёртывание отдельно.
2. Проверка реализованного прямого сеанса на физических машинах; оптимизация видеотракта и устойчивая идентичность устройств поверх приглашений.
3. Платформенные адаптеры: Windows, ScreenCaptureKit/macOS, X11 и Wayland/порталы, Android MediaProjection уже интегрирован; требуется runtime-проверка на телефонах.
4. Android SAF для файлов, подписанные сборки/обновления, тестовая матрица физических устройств.
5. Командные роли, биллинг и self-hosting после проверки пилота. Монетизация описана как гипотеза в PRODUCT-BRIEF.md.

Медиатракт и сервер не заменяются демонстрационными таймерами или ложными индикаторами подключения.

## Сеанс 0.4

Общая доска ограничена 128 штрихами по 128 точек; хост упорядочивает оба источника. Окно annotations-overlay имеет только read-only IPC, основная страница — явно перечисленные команды. Наложение основного монитора выключается до медленной очистки файлов.

PCM 48k/16-bit/stereo идёт бинарными 20ms пакетами с epoch/sequence, обе очереди ограничены 200ms. AudioBatch отдаёт метаданные и звук атомарно; UI очищает WebAudio при отзыве, смене сеанса и отключении. Владелец разрешает capture отдельно.

Сменить монитор при управлении пока нельзя: отсутствует сквозной screen epoch/ack кадра. Это отдельный следующий слой. Только-видео сеанс позволяет владельцу сменить экран и очищает доску.
